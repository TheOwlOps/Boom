# Test Writer

Analyze functions with AST then auto-generate pytest test cases:

- **Happy path:** call the function with sample values inferred from variable names /
  annotations / defaults (e.g. `email` → `"test@example.com"`, `count: int` → `5`).
- **Edge cases:** `None`, empty (`""`/`[]`/`{}`), boundary (`0`, `-1`).
- **Smart asserts:** if the function body is simple (1 computable `return` statement),
  compute the expected result and generate a real assert; otherwise leave a `TODO`
  for the developer to fill in.

## When to use

- Just wrote a new function, need tests quickly
- Adding tests to old code that has none
- When the user says "write tests for this function", "generate tests", "add test cases"

**Not for:** complex methods needing object setup (the skill generates
placeholders, the developer fills them in); complex async code.

## Input

- **Source file:** 1 `.py` file (analyzes module-level functions)
- **Parameter:** module name to import in the test (default: source file name)

## Output

A `test_<name>.py` file, standard pytest:

```python
"""Test auto-generated by the test-writer skill — review and fill in TODO asserts."""
import sys
from pathlib import Path

import pytest

sys.path.insert(0, str(Path(__file__).resolve().parent))

from my_module import add, greet


def test_add_happy_path():
    """Happy path: call with valid sample values."""
    assert add(1, 2) == 3


def test_add_none_input():
    """Edge case: None input — check the function handles it safely, no crash."""
    # TODO: assert the expected behavior (raise or return what)
    add(None, 2)


def test_add_boundary_zero():
    """Edge case: boundary value: 0."""
    # TODO: assert the expected behavior (raise or return what)
    add(0, 2)
```

## Example

### CLI

```bash
# Print tests to stdout
python3 skills/test-writer/writer.py agent/src/my_module.py

# Write to tests/test_my_module.py next to the source
python3 skills/test-writer/writer.py agent/src/my_module.py -o tests/test_my_module.py

# Run the generated tests
python3 -m pytest tests/test_my_module.py -v
```

### Python API

```python
from skills.test_writer.writer import generate_tests, write_tests

# Generate from a source string
result = generate_tests("def add(a, b):\n    return a + b\n", module_name="my_module")
print(result.test_code)       # test file content
print(result.functions)       # ['add']

# Generate and write next to the source
out = write_tests("agent/src/my_module.py")
print("Written:", out)
```

## Sample value inference

Priority order: **default** → **variable name** (regex: email, password, url, path,
count, price, items...) → **annotation** (`int`→`1`, `str`→`"sample"`,
`list`→`[1, 2, 3]`...) → `"None"`.

## Pitfalls

- Generated edge-case tests are scaffolding: they run immediately but asserts are
  still `TODO` — the developer must assert the expected behavior before trusting them
- Expected results are only computed for simple functions (1 `return`, no other
  function calls, no attribute access) — for more complex functions the happy path is TODO too
- Skips methods inside classes and functions whose names start with `_`
